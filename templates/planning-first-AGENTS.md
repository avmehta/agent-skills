## Planning-first working agreement

Slow down to speed up. For substantive work, inspect first, clarify with `socratic-planning`, write a concrete plan, stress-test it with `contrarian-review`, and wait for explicit approval before editing production code. A user may explicitly waive the gate or provide an already-approved spec.

Keep scope tight, preserve unrelated changes, and ask before production dependencies, destructive actions, external writes, or material scope expansion. Verify the implementation against explicit acceptance criteria and never claim an action or test occurred unless it did.

At the start of consequential work, recall durable project context when a memory tool is available and verify it against the repository. At the end, use `wrap-up` to preserve decisions, verification, open risks, and the exact next step. Never store secrets, credentials, personal data, raw logs, or speculation in memory.
